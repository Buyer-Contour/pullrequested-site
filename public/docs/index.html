01 / Intake

Find an offer. Send a brief.

Read offer.json for prices, deliverables, acceptance criteria, and links. Fixed-price services already have Stripe Checkout links. For scoped work, send a brief and wait for a reply with the terms and, when applicable, a signed quote. For the free sample, ask for three evidence-brief rows and include your target accounts or criteria and roles.

curl -fsS https://phantompipe.com/offer.json

# This POST sends a real inquiry. Replace the example fields first.
curl -i https://phantompipe.com/quote \
  -H 'Content-Type: application/json' \
  -d '{"name":"Your name","email":"you@example.com","service":"pipeline-research","brief":"Please send the three free evidence-brief sample rows for our target accounts: …"}'

# Replace with the status_url returned by POST /quote.
curl -i 'https://phantompipe.com/quote/status/REQUEST_ID'

A successful POST returns 202 Accepted and a receipt: request_id, status: "received", response_window: 48 (hours), and status_url. The receipt is available for up to 30 days and confirms intake only. Replies go to the supplied email; there is no endpoint for retrieving a signed quote by request ID.

Supported service values are pipeline-research, gtm-data-ops, outbound-systems, gtm-automation, and not-sure. company is optional. For form-encoded requests include form-name=quote and Accept: application/json to get a receipt. Do not send card details or confidential data.

02 / Settlement

Pay an issued quote.

Stripe Checkout: Open the published card link for a fixed-price service, or use the issued /q/{signed_quote_token} link for an eligible custom quote. Follow the page to Stripe Checkout and keep the Stripe receipt. After payment for a fixed-price service, send the service name, checkout email, and brief.

curl -i 'https://phantompipe.com/q/SIGNED_QUOTE_TOKEN'

# For a Stripe-eligible quote, creates or resumes Checkout; does not charge.
curl -i -X POST 'https://phantompipe.com/api/checkout?quote=SIGNED_QUOTE_TOKEN'

Tempo MPP: For a quote that specifies MPP, fetch the signed payment URL to obtain a 402 challenge in WWW-Authenticate. An MPP-compatible Tempo wallet signs a credential. Retry the same signed URL with Authorization: Payment …. A successful settlement returns 200, a JSON receipt, and Payment-Receipt. MPP can be unavailable (503); never switch rails without confirming which your quote permits.

curl -i 'https://phantompipe.com/api/mpp/pay?quote=SIGNED_QUOTE_TOKEN'

# This retry can settle a real payment. Only use a buyer-approved credential.
curl -i 'https://phantompipe.com/api/mpp/pay?quote=SIGNED_QUOTE_TOKEN' \
  -H 'Authorization: Payment MPP_CREDENTIAL'

If the published MPP link has ?product=, the first request redirects to a freshly signed URL. Save that URL and use it for the challenge, retry, or resume. Do not reopen the listing to resume, and do not send a credential to the listing URL. The evidence-brief marketplace batch is for agreed, accepted rows, not the free sample.

Stripe agent payments: On an eligible quote, GET /api/pay?quote=… returns a quote-pay-v1 challenge. The challenge specifies the nonce and accepted Stripe token types. POST one eligible Stripe token and the nonce; then redeem the resulting PaymentIntent ID with X-PAYMENT as shown in the OpenAPI reference. Never POST raw card data.

x402: Not supported as a payment rail. The legacy manifest lists free resources only. Neither MPP nor the Stripe agent 402 challenge is x402. Quote tokens and payment credentials authorize payment operations; treat them as private. There is no standalone payment-status endpoint. Use the receipt from the payment rail, not the intake receipt or the Checkout return page.

03 / Model Context Protocol

Connect an MCP client.

Use https://phantompipe.com/mcp with the stateless Streamable HTTP transport. No authentication, session ID, or server event stream is required. A Streamable HTTP client sends JSON-RPC requests by POST and receives JSON responses. The server card provides the endpoint for discovery.

Cursor with native remote MCP: add this entry to your mcpServers config.

{
  "mcpServers": {
    "phantom-pipe": {
      "url": "https://phantompipe.com/mcp"
    }
  }
}

Claude Desktop or Cursor via a local bridge: if you use a local command-based MCP config, add this entry to mcpServers. It requires Node.js and npx.

{
  "mcpServers": {
    "phantom-pipe": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://phantompipe.com/mcp"]
    }
  }
}

Generic HTTP client: send initialize, then notifications/initialized, and use the negotiated MCP-Protocol-Version header with tools/list and tools/call. Only protocol version 2025-03-26 supports JSON-RPC batches; newer versions accept one message per request. Use Content-Type: application/json and Accept: application/json, text/event-stream for POST. GET shows a short endpoint description, or returns 405 if the client requests an event stream.

curl -fsS https://phantompipe.com/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"example","version":"1.0"}}}'
  • list_offers and get_offer: read prices, samples, deliverables, and available payment links.
  • submit_brief: with buyer permission, send the same inquiry as POST /quote. To request the free sample, choose pipeline-research and ask for the three free rows in the brief.
  • get_quote_request_status: check whether an intake receipt is still available.
  • get_quote_payment_links: build links for an already-issued quote token; does not issue or validate a token, initiate payment, or check settlement.

04 / Operational details

Limits, errors, and related APIs.

The application does not set a requests-per-minute limit for these endpoints. Quote intake accepts up to 32 KiB per request; MCP accepts up to 64 KiB. The Stripe agent payment POST parses JSON bodies up to 2,048 characters. Hosts and payment providers may enforce their own limits.

Intake returns 400 for invalid fields, 413 for a body over the limit, 415 for unsupported content types, and 502 if intake cannot confirm forwarding. A 503 with a request_id means the brief was forwarded but the receipt could not be saved; contact dane@phantompipe.com with that ID rather than submitting again. An invalid or expired receipt returns 404.

In payment flows 402 can be a challenge or a rejected payment, 409 means paid, reserved, or replayed, 410 means the quote expired or is too close to expiry, and 422 indicates the wrong rail. Save the final signed URL and any payment receipt; don’t open a fresh listing or retry a charge blindly. MCP distinguishes protocol errors (error) from tool failures (result.isError).

The separate Pricing Page Change Monitor uses RapidAPI authentication and plan limits. It is not a Phantom Pipe MCP tool.
